## Current venue (most important)

- **Post in Nervos Talk → `daos-funding` → `Spark Program` sub-section.**
- The old `Spark-Program` tag is **no longer required** after the 2026-07-19 forum update; the sub-section is the venue.
- Title format: `Spark Program | The Project Title`.
- Bilingual is **no longer mandatory** (2026-04-27 update); at least English is required. The forum has AI translation.
- Since 2026-07-28, applicants must also create the Spark project repository under their own GitHub account as identity proof. Multiple applicants: main applicant creates it, others fork.

## Funding

- Standard request: **~$1,000**.
- Single-category projects can request up to **$2,000** with a detailed complexity justification.
- Overall ceiling: **$2,000**.
- Payment can be **100% CKB**, or CKB + USDI with USDI ≤ 50%.
- Funding is managed through a multi-sig wallet requiring at least 3 Committee confirmations.
- Distribution: **20% upfront**, then 80% on-demand at weekly syncs or at completion.
- One Spark grant per project, in principle.
- Timeline: 1–2 months; template recommends 4–8 weeks, max 12 weeks.
- Extensions: request at least 1 week before the deadline; usually ≤2 weeks.

## Process

1. Post the proposal in the Spark Program sub-section on Nervos Talk.
2. Committee reviews within **1 week**.
3. Approved projects are announced on Nervos Network Discord + Nervos Talk.
4. Weekly syncs: technical progress, user feedback, iteration, funding use.
5. Monthly community livestream.
6. Completion: public summary report, plan-vs-actual, decisions, funding usage report, code repo, demo, docs, user-validation material.

## Proposal template (post #7, 2026-06-16)

0. Title & tags
1. Project overview
2. Team profile (Discord + email required)
3. Project background
4. Solution
5. Technical approach
6. To-do list (weekly, 4–8 weeks, ≤12)
7. Required funding & breakdown
8. Deliverables + how to verify (non-code verification is important)
9. Current state vs funded work
10. CKB alignment

## Evaluation focus

- Web5 philosophy and real community need.
- Technical feasibility and innovation.
- User testing / operational plan where applicable.
- Team capability and fit.
- Potential value to the CKB ecosystem.
- Quality control: no unreviewed generated content, no format chaos, no “free money” applications. Using AI is fine; understanding and judgment are not optional.
